# 로그인된 Headless Chrome의 Netflix 전편 영어 수집

**2026-10-24 실제 S02E03·S02E04의 영어 CC 파일 전량 확보와 독립 검사를 통과했다.** 사용자가 전용 Chrome 창에서 정상 로그인·프로필 선택을 한 뒤 같은 전용 프로필을 headless로 재실행했다. 빈 프로필 시험이나 합성 원문이 아니다.

E06은 사용자가 E05를 1.25배속으로 시청하는 동안 수행했다. [동시 시청 시험의 전·중·후 측정과 파일 검사](CONCURRENT_HEADLESS_CAPTURE.md)를 따로 기록했다. 아래 초기 E03/E04 설명은 당시 두 회차 성공의 이력이다.

확보한 세 회차 모두 `webvtt-lssdh-ios8` 영어 CC 단일 전체 파일이다. 경고 0개, UTF-8 BOM을 포함한 원본 바이트 SHA-256, 별도 파서의 모든 ID·시각·본문·입력 항목 대조, VTT 왕복 검사를 통과했다. 마지막 자막 시각으로 전편을 추정하지 않았다.

원본 바이트 SHA-256:

- E03: `8fa1f2b1fec9b7e8ef656fc5795708f73adb3ec3c6454ddcee710d5d89023ba0`
- E04: `711da74485d7a279a099c44770de2ba3d7d392ad96cfdfe297cf94f3f7a4311e`
- E06: `28e487b5abd21059737e75aec3dafdd1658a3347c215336031040ec3884839b3`

개인 원본·증거는 `private-subtitles/netflix-native-20261024/headless/` 아래 `S02E03/`, `S02E04/`, `S02E06/`에 보존했다. 각 폴더에 원본 캡처 JSON, BOM 포함 원본 VTT, 파이프라인용 EN VTT, `capture-audit.json`, `run-report.json`, 실제 headless 화면이 있다. E06에는 동시 시청 측정과 실제 회차 선택 근거도 있다. 원래 EP3 번역 작업의 SHA-256도 이전과 일치한다. 기존 영어/A/B 파일이나 번역 응답을 새 원문으로 대체 사용하지 않았다.

## 실행

이 PC에서는 설치된 Chrome 155.0.8059.85와 번들 Playwright 1.62.1을 사용했다. 이미 설치된 Playwright는 프로젝트 또는 번들 runtime 경로에서 찾으며 자동 설치하지 않는다. 다른 환경은 `--runtime-root NODE_MODULES_PATH`, `--chrome CHROME_EXE_PATH`를 명시할 수 있다.

최초 1회 전용 프로필 로그인:

```powershell
npm run netflix:login
```

열린 Netflix 창에서 정상 로그인하고 프로필을 선택하면 도구가 회원 내비게이션을 확인한 뒤 그 창을 닫는다. 사용자 기본 Chrome 프로필/쿠키/비밀번호를 복사하거나 추출하지 않는다. 전용 상태는 Git/배포 제외 경로 `private-subtitles/headless-auth/profile` 안에 Chrome이 관리하며 보관한다.

그 다음부터는 창 없이 실행한다.

```powershell
npm run netflix:capture -- --video-id 70262107
npm run netflix:capture -- --video-id 70262108
```

로그인이 만료되면 성공으로 넘어가지 않고 `headless_login_not_confirmed`로 중단한다. 단일 실행 lock을 두어 전용 프로필을 중복 실행하지 않는다. 각 실행은 새 증거 폴더에 보존하고 원본을 덮어쓰지 않는다. 종료 코드 0은 전편 독립 검사까지 통과했을 때이며, 실패/미검증은 2다. `--setup`은 인증 준비만 별도 수행한다.

## 수집·검사 경로

1. 로그인된 전용 프로필을 `--headless`로 실행하고 보이는 회원 내비게이션으로 인증 유지 여부를 다시 확인한다.
2. 기존 `core.js`, `netflix.js`, `netflix-main.js`를 페이지 시작 전에 설치한다. Chrome 확장 자체를 자동 설치하거나 확장 관리 URL에 접근하지 않는다.
3. 현재 watch ID에 명시적으로 일치하는 manifest의 영어 비강제 트랙을 고른다. manifest가 제공한 자막 CDN의 단일 전체 텍스트 파일만 받는다.
4. `capture-validation.js`로 회차·언어·전편 메타데이터, 원래 0/1 보정, 모든 입력 항목, 원본 바이트 해시/BOM, 독립 재파싱을 검사한다.
5. 기존 `inspect-netflix-capture.mjs`를 별도 Node 프로세스로 다시 실행해 캡처 JSON·원본 VTT·파이프라인 VTT·검사 JSON을 생성한다.
6. 검사까지 통과한 경우에만 `fullSubtitleFileAcquired: true`를 기록한다. 사용자 시청 탭에는 재생·정지·탐색·새로고침·종료 명령을 보내지 않는다.

DRM 미디어·라이선스·키 수집, 내부 Netflix 플레이어 API, 쿠키 내보내기, User-Agent 위장, 보안/DRM 우회를 사용하지 않는다. 공개 EME API의 Widevine 지원 여부만 실행 조건으로 기록했다.

## 첫 실패와 실행 설정 수정

16:01:33의 첫 인증된 headless 시도는 **M7701-1003**, manifest 미확보로 끝났다. 화면과 실패 보고서는 보존했다. [Netflix 공식 안내](https://help.netflix.com/en/node/27451/)는 이 오류를 브라우저 설정·지원 버전·콘텐츠 보호 컴포넌트 문제와 연결한다.

이후 [Playwright 기본 실행 인자](https://github.com/microsoft/playwright/blob/main/packages/playwright-core/src/server/chromium/chromiumSwitches.ts)를 사용하지 않고, 전용 `--user-data-dir`, 로컬 디버깅 pipe, `--headless`, 최초 실행 방지 정도만 명시해 **일반 Chrome 기본 동작을 유지**했다. 샌드박스는 유지했고 컴포넌트 업데이트·Chrome 기본 기능을 자동화 기본 인자로 끄지 않았다. 그 실행에서 공개 EME의 Widevine 지원이 확인됐고 두 회차 수집이 성공했다.

여러 기본 인자가 함께 바뀌었으므로 특정 옵션 하나만 원인이라고 확정하지 않는다. 현재 성공 설정과 실패 설정의 차이를 보존하며 임의의 보안·보호 콘텐츠 설정 변경을 해결 방법으로 사용하지 않았다.

## 확인 범위와 남은 연결

전 시즌의 실제 회차 발견·영속 대기열·순차 수집·재개 도구를 추가했다. 실행과 완료 판정은 [SERIES_COLLECTION.md](SERIES_COLLECTION.md)를 참고한다. 전 시즌 성공 여부는 개인 대기열의 실제 검사 결과로 판단한다.

- 이 PC·계정·전용 프로필·세 회차에서 **화면 없는 영어 전체 파일 확보**를 실제 확인했다. 앞으로 매번 일반 Chrome 창을 사용자가 열어야 한다는 조건은 없다. 로그인 만료 시 재인증은 필요할 수 있다.
- 원본 파일 전량 확보 확인이며 모든 음성의 전사·번역 의미·시청 싱크 평가는 아니다. 실제 영상 재생 완료도 검사하지 않았다. 수집 직후 screenshot에 로딩 화면이 남아 있어도 성공 판정은 화면이 아니라 원본 파일과 독립 검사 결과에 근거한다.
- 일반 Chrome **비활성 탭 대기열**의 최초 로드는 여전히 별도 미검증이다. headless 성공을 그 경로의 성공으로 확대하지 않는다.
- 현재는 별도 실행 도구다. 확장 팝업/브리지의 headless 실행 버튼, 시즌 회차 자동 발견, 수집 결과의 라이브러리 자동 등록·번역 시작까지 연결됐다는 뜻은 아니다.
- 추가 E06 시험에서는 실제 E05 시청과 병행한 전편 확보를 확인했다. 이 한 번의 결과를 무제한 병렬 수집으로 확대하지 않는다. 각 시험은 한 회차씩 수행하고 수집 브라우저를 닫았다.
