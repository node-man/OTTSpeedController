# Netflix 영어 자막 수집 검증

실제 S02E03의 **전편 원본 파일 확보 가능성 확인**을 먼저 마쳤고 후속 [ChatGPT MCP 브리지](CHATGPT_MCP.md)를 구현했다. 기존 SMI, 외부 VTT, 이전 번역 응답을 이번 수집의 원본으로 사용하지 않는다. 실제 MCP 연결·번역 반환·표시의 완료 여부는 수집 성공과 별도로 확인한다.

## 구현한 수집 경로

2026-10-24 [백그라운드 사전 수집 대기열](BACKGROUND_COLLECTION.md)을 추가했다. 명시한 회차 주소를 비활성 Chrome 탭에서 하나씩 수집하도록 구현했고 시청 탭이 있으면 대기한다. 구현·합성 검사는 통과했으나 실제 Netflix 비활성 탭 수집은 미확인이다. 아래 S02E03 실측은 기존 사용자 작업실 수집 경로의 기록이다.

- Netflix 페이지 시작 시 MAIN world에서 manifest JSON과 WebVTT 프로필 요청을 관찰한다.
- 현재 `/watch/<videoId>`와 명시적으로 일치하는 manifest의 영어 비강제 트랙만 선택한다.
- `timedtexttracks`/`textTracks`, URL 맵과 URL 배열을 처리한다. 전체 자막 파일을 읽은 뒤 VTT 또는 TTML을 파싱한다.
- 자막 ID·시각·본문, 파일 바이트 해시, 입력·수용·제외 개수와 사유를 기록한다. 기존 A/B는 보존하며 수집 원문에는 외부 보정을 적용하지 않는다.
- 내부 Netflix 플레이어 상태/API 접근은 사용하지 않는다. DRM 미디어 수집·복호화도 수행하지 않는다.
- manifest의 단일 전체 파일 프로필, HTTP 본문 전체 수신, 완전한 문서 파싱과 항목 수 대조가 모두 있어야 전편 파일 확보로 판정한다. 마지막 cue가 영상 끝에 가까운지는 전편 판정 근거로 사용하지 않는다.

## 실제 확인 상태

2026-10-24 후속 [로그인된 headless 수집](HEADLESS_CAPTURE.md)에서 E03·E04의 영어 전체 파일을 새로 확보하고 독립 검사했다. E03 1,831개·E04 1,867개를 전부 수용했고 제외·경고 0개, 바이트 해시/BOM·별도 재파싱·VTT 왕복 검사 통과다. 초기 빈 프로필의 NSES-404 실패와 아래 2026-10-23의 기존 사용자 작업실 수집 성공을 별도 이력으로 보존한다.

2026-10-23 **실제 S02E03 영어 자막 전체 파일 확보와 별도 검사에 성공했다.** Netflix `70262107`의 영어 비강제 CC 트랙, `webvtt-lssdh-ios8` 단일 전체 파일을 사용자 작업실에서 수집·내보낸 후 `inspect-netflix-capture.mjs`로 검사했다.

| 검사 항목 | 실제 결과 |
| --- | --- |
| 수집 시각 (한국) | 2026-10-23 23:30:25 |
| 별도 검사 시각 (한국) | 2026-10-23 23:34:43 |
| 회차 식별 | `netflix:70262107` — 저장 세션·트랙 수집 기록 일치 |
| 원본 입력 / 수용 / 제외 | 1,831 / 1,831 / 0 |
| 경고 | 0 |
| 자막 시각 범위 | 00:05.046–42:35.594 |
| 원본 크기 | 294,215 바이트 (UTF-8 BOM 포함) |
| 바이트 해시 / 모든 cue 재파싱 / VTT 왕복 검사 | 모두 통과 |
| 외부 SMI·A·기존 번역을 원문으로 사용 | 없음 |
| 시간 보정 | 오프셋 0, 배율 1 |

비공개 보존 경로는 `private-subtitles/netflix-native-20261023/S02E03/`이다. `capture.original.json`은 내보낸 JSON 그대로, `netflix.original.vtt`는 다운로드 바이트 그대로, `netflix.en.vtt`는 기존 파이프라인용 VTT이며 `capture-audit.json`에 판정 근거와 해시를 보존했다. 원래 파일을 재구성할 때 TextDecoder가 제거한 UTF-8 BOM을 복원했고, 복원한 바이트가 수집 당시 SHA-256과 일치함을 확인했다.

전편 판정은 현재 회차 manifest의 단일 전체 파일 프로필, 완전한 문서, 입력 항목 전량 대조를 근거로 한다. 마지막 자막 시각만으로 판정하지 않았다. 이는 Netflix가 제공한 자막 파일 전량 확보 확인이며 모든 음성이 자막에 표현됐다는 보장은 아니다. 실제 음성과의 싱크, ChatGPT MCP 연결, 새 번역 B 반환·표시는 이번 수집 검사에서 확인하지 않았다.

최초 두 시도는 파일 확보에 실패했으며 두 번째 진단은 `JSON 검사 7 / 현재 회차 자막 목록 0 / 영어 0 / 파일 0 / VTT 요청 4`였다. 이후 `capture-3`는 이미 파싱된 JSON을 폭 우선 탐색하고, 목록 객체 형태와 추가 필드 표기를 처리하여 실제 수집에 성공했다. 파일을 못 찾으면 URL·토큰·대사 본문 없이 필드명과 회차 식별 구조를 담은 `OTTSpeed_Netflix_<id>.diagnostic.json`을 자동 저장한다. 합성 시험과 실제 수집 결과는 구분한다.

## 설치 및 자료 확인

`npm run package` 결과인 `dist/OTTSpeed-1.1.0` 또는 현재 소스 폴더의 확장을 새로고침하고 Netflix 탭도 새로고침한다. 작업실에서 **Netflix 영어 트랙 확인 → 영어 트랙 선택 → 선택한 영어 자막 수집 → 수집 원본·검사 기록 저장** 순으로 사용한다.

실제 수집 파일은 다음 명령으로 독립 검사한다. 출력 디렉터리는 새 디렉터리여야 한다.

```powershell
node scripts/inspect-netflix-capture.mjs INPUT.capture.json private-subtitles/netflix-native-20261023/S02E03 70262107
```

검사기는 회차·언어·0/1 보정, 원래 파일 바이트 해시, 별도 재파싱 결과와 모든 cue를 대조한다. 입력 원본과 VTT·검사 기록을 개인 디렉터리에 보존한다. 작품 본문이나 서명된 다운로드 URL을 공개 저장소에 커밋하지 않는다.

2026-10-24 영한 병기 확인에서 이 Netflix 프로필의 비표준 `</c.class>` 닫는 태그가 원문에 남는 표시 문제를 발견했다. 새 수집의 파서는 이 서식도 제거한다. 이미 확정한 요청은 원문·해시·ID·시각을 수정하지 않으며, Netflix VTT 수집 이력이 있는 기존 원문의 화면 표시에서만 잔여 닫는 태그를 제거한다. 새로 파싱한 본문이 달라지면 새 요청으로 처리한다. 기존 캡처의 검사 기록은 당시 파서 기준의 불변 기록이다.

## 관련 자동 검사

`npm test`, `npm run check`, `npm run package`를 사용한다. `tests/netflix-capture.test.mjs`는 합성 manifest/자막으로 구·신 형식, 회차 일치, 전체 파일 파싱, 누락 판정, 다운로드 중 회차 변경을 검사한다. 작업실 시험은 A/B 보존과 잘못된 회차 저장 차단도 검사한다. 실제 수집 범위·시청 싱크는 별도로 확인해야 한다.
